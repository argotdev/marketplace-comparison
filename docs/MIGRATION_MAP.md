# Sendbird to Stream migration map

Every Sendbird concept the Sendbird adapter (`packages/adapters/sendbird`) and its server half use, mapped to what the Stream adapter (`packages/adapters/stream`) does instead. Sources: the two adapters, and Stream's migration docs (https://getstream.io/chat/docs/node/migrating-from-sendbird/, https://getstream.io/blog/sendbird-migration/, https://getstream.io/chat/docs/javascript/import/). Status 2026-10-06: both adapters are written and type-checked; neither has run against an account yet.

| Area | Sendbird (as used) | Stream (as used) | Notes |
|---|---|---|---|
| Client SDK | `@sendbird/chat` 4.22.13 + `GroupChannelModule` | `stream-chat` 9.54.0 | Same package serves the Node server in Stream; Sendbird's server side is the Platform API over REST. |
| App credentials | Application ID (case-sensitive) + master API token (secondary tokens for API calls) | API key + API secret | Stream's key is public (in the browser); the secret stays on the server. Sendbird's App ID is public too. |
| Init | `SendbirdChat.init({ appId, modules })` | `StreamChat.getInstance(apiKey)` | |
| Connect | `sb.connect(userId, sessionToken)` + `SessionHandler.onSessionTokenRequired` for refresh | `client.connectUser({ id, name, language }, token)`; token provider function for refresh | Stream tokens are JWTs signed with the secret; no expiry unless you set one. Sendbird session tokens expire (default 7 days) and the SDK asks for a new one. |
| Token issuance (server) | `POST /v3/users/{id}/token` | `serverClient.createToken(userId, exp)` | Stream signs locally; no network call. |
| Users | `POST /v3/users` (`user_id`, `nickname`, `profile_url`, `metadata`) | `client.upsertUsers([{ id, name, image, ...custom }])` | Stream custom fields are top-level on the user object; Sendbird uses string `metadata`. User id charset on Stream: `a-z 0-9 @ _ -`. |
| Channel kind | Group channel (`isDistinct: false`) | Channel type `order` (custom type created server-side with `createChannelType`) | Stream's `messaging` type is the default equivalent of a group channel; `livestream` maps to Sendbird open channels. We used a custom type so permissions, block lists and reminders can be tuned for order chats only. |
| Channel id | `channelUrl: 'order-<id>'` | `client.channel('order', 'order-<id>')` | Both accept a client-chosen id. Stream ids: ≤64 chars. |
| Channel custom type | `customType: 'order'` (free string, settings per custom type via Platform API) | The channel *type* itself (`order`) | In Sendbird the custom type is a label on a group channel with optional per-type settings; in Stream the type is a first-class config object (events, permissions, moderation). |
| Channel metadata | `data: JSON.stringify({ orderId, listingId })` (string) and/or `createMetaData` (string key/values) | `{ orderId, listingId }` as top-level custom fields on channel data (≤5 KB) | Stream stores typed JSON; no stringify. |
| Members | `invitedUserIds: [buyer, seller]` (auto-accept default) | `members: [buyer, seller]` on create | |
| Add the agent | `channel.inviteWithUserIds(['agent_sam'])` | `channel.addMembers(['agent_sam'], { text })` | Stream needs the `update-channel-members` grant for `channel_member` if a member (not an admin) does it; we added it to the `order` type. |
| Custom message (order card) | User message with `customType: 'order_card'` and `data: JSON.stringify(card)` | Message with a custom attachment `{ type: 'order_card', card }` | Stream's migration guide maps Sendbird `custom_type` to a custom attachment or custom message fields. We chose an attachment so the kit's `Attachment` override renders it. |
| Edit the card (server) | `PUT /v3/group_channels/{url}/messages/{id}` with `message_type: MESG`, `data` | `client.partialUpdateMessage(id, { set: { attachments } }, userId)` | Both fire an update event (`onMessageUpdated` / `message.updated`). |
| Text message | `channel.sendUserMessage({ message })` with `.onSucceeded/.onFailed` handlers | `await channel.sendMessage({ text })` | Promise vs handler object. |
| File message | `channel.sendFileMessage({ file, fileName, mimeType })` → `message.url` | `channel.sendImage(file)` → `channel.sendMessage({ attachments: [{ type: 'image', image_url }] })` | Two calls on Stream; the CDN URL is signed and member-only. |
| Receive | `GroupChannelHandler({ onMessageReceived, onMessageUpdated, ... })` registered by id | `channel.on('message.new' | 'message.updated', handler)` returning `{ unsubscribe }` | |
| History | `channel.getMessagesByTimestamp(ts, { prevResultSize })` | `channel.query({ messages: { limit } })` or `channel.state.messages` after `watch()` | |
| Read receipts | `channel.markAsRead()`; `onUserMarkedRead(channel, userIds)`; `getReadMembers(message)` | `channel.markRead()`; `message.read` event; `channel.state.read` | |
| Typing | `startTyping()` / `endTyping()`; `onTypingStatusUpdated(channel)` + `getTypingUsers()` | `keystroke()` / `stopTyping()`; `typing.start` / `typing.stop` events | Stream's `keystroke()` throttles itself. |
| Moderation (filter) | Profanity filter `regex_filters` (RE2) on channel type `order`, `type: 1` (replace) via `PUT /v3/applications/settings_by_channel_custom_type/order` | Block lists (`createBlockList` with `type: 'regex' | 'word'`) + moderation policy `upsertConfig({ key: 'chat:order', block_list_config, automod_platform_circumvention_config })` | Sendbird masks in place (asterisks); Stream's actions are `flag`, `remove` (block), `shadow`, `bounce`. Stream also has built-in phone/email/link detection (platform circumvention). |
| Moderation (report) | `channel.reportUser(user, ReportCategory.SUSPICIOUS, text)`; `user:report` webhook; `GET /v3/report` | `client.flagUser(id, { reason })`; `user.flagged` webhook; `moderation.queryReviewQueue()` | |
| Translation | `translationTargetLanguages: ['en','es']` on send → `message.translations` (sales-enabled) | `updateAppSettings({ auto_translation_enabled: true })` + `user.language` → `message.i18n.<lang>_text` (Elevate+) | Sendbird translates per request; Stream translates per reader language automatically. |
| Push | Not supported for browsers in the JS SDK | Not supported for browsers | Both need a webhook-driven notifier for web. |
| Email | None; `group_channel:message_send` webhook → our mailer | None; `message.new` webhook → our mailer (or `user.unread_message_reminder` events) | |
| Webhooks | `PUT /v3/applications/settings/webhook`; header `x-sendbird-signature` = HMAC-SHA256(master token, raw body) | `updateAppSettings({ event_hooks: [...] })`; header `X-Signature` = HMAC-SHA256(secret, raw body); `client.verifyWebhook(rawBody, sig)` | Stream's `event_hooks` array replaces the whole list on update. |
| Presence (server) | `GET /v3/users/{id}` → `is_online` | `queryUsers({ id }, {}, { presence: true })` → `online` | |
| Support desk | Sendbird Desk (separate product: tickets, agent routing, dashboard UI) | None; integrate a desk or build a support channel type | Stream's honest gap. |
| Activity feeds | None | Feeds v3 (`@stream-io/feeds-client`, `@stream-io/node-sdk`): feed group `listing`, activity `order_status` | Sendbird's honest gap. |
| Data migration | Data export (Platform API, JSON/CSV; plan-gated) | Import: JSON Lines (`user`, `channel`, `member`, `message`, `reaction`) via `getstream import chat`; real-time sync by pointing Sendbird's webhook at `https://chat.stream-io-api.com/sendbird/webhook?api_key=…` (Enterprise) | Mapping from Stream's docs: `open_channel` → `livestream`, `group_channel` → `messaging`, `UserMessage/FileMessage` → message + attachments, `ADMM` → system message, metadata → custom fields (≤5 KB). |
